## Findings

### 1. HIGH — real residents' document scans are committed to a public repo
`Teresa-Mobile-App/Reference_forms/Teresa, Rizal  File/` (66 MB, 84 files) contains 18 JPEG

> The individual names are **withheld from this file because this repository is public** —
> naming them here would publish exactly the index this finding exists to prevent. The
> unredacted list is in the owner's local copy, `Teresa-Rizal-Mobile-SWEEP-full-2026-08-29.md`.
> `ls` the directory above to see them if you have legitimate need.

These are reference forms for building the app — they do not belong in the shipped repo at all,
let alone a public one. Removing them from `HEAD` is not enough; they stay in history and in
every existing clone/fork. Fixing this properly means history rewrite + force-push + credential
rotation-equivalent (assume they have been fetched).

### 2. HIGH — the mock "demo" identity is a real resident's record
`lib/services/mock_catalog.dart:2572` states plainly that the verified demo account is a named
resident's **actual** Constituents record from the Web Admin's own mock data — id, name, email,
birthdate, civil status, occupation, address, household and family IDs all sourced from that
record, not fabricated. The bundled demo ID images under `assets/images/` print that person's
real details, and the same pattern applies to the other two seeded demo identities.
A public demo app should ship synthetic identities. (Names withheld — see finding 1.)

### 3. HIGH — a corrupt/incompatible saved session hangs the app on the splash forever
Every service's restore path does an unguarded `jsonDecode` + `fromJson`, and no service has a
`try`/`catch` around it:

- [citizen_session_service.dart:49-63](Teresa-Rizal-Mobile/Teresa-Mobile-App/lib/services/citizen_session_service.dart#L49-L63)
- [requests_service.dart:74-92](Teresa-Rizal-Mobile/Teresa-Mobile-App/lib/services/requests_service.dart#L74-L92)
- also `balita_service`, `master_file_service`, `notifications_service`, `resident_profile_service`

Those `fromJson`s decode enums with `Enum.values.firstWhere(...)` and **no `orElse`**
(`service_request.dart:210`, `announcement.dart:125`, `receipt.dart:61`, `attachment.dart:86`),
so any renamed/removed enum value, or any malformed payload, throws.

The throw happens inside a future started from the constructor, so it is unhandled: `_loading`
is never set false and `notifyListeners()` never fires. `AuthGate`
([main.dart:78](Teresa-Rizal-Mobile/Teresa-Mobile-App/lib/main.dart#L78)) then renders a
`CircularProgressIndicator` **forever**. Only clearing app data recovers it.

This is not hypothetical for this codebase — it already ships five separate migrations for
persisted data that changed shape (`_migrateStaleDemoIdentity`, `_migrateSeniorCitizenIdCategory`,
`_migrateObsoleteTrackingLabels`, ...), all of which run *after* the `fromJson` that would throw.

Fix: wrap each `_restore()` body in `try`/`catch`, fall back to empty state, and give every
enum `firstWhere` an `orElse`.

### 4. MEDIUM — status vocabulary has drifted from the web platform
Canonical list in `Teresa-Rizal-Web-Platform/CLAUDE.md` (15 statuses) vs mobile's
`lib/theme/app_status.dart` (15 statuses):

- Mobile is **missing `Resubmitted`**, which is canonical on the web side (8 files) and which
  mobile's own `requests_service.dart:964` writes into `statusHistory` as a literal string.
  It renders fine today (the timeline prints the raw label), but

  route through `fromLabel` will show a resubmitted request as grey "Draft".

  web platform — against the "never invent new status labels" rule both CLAUDE.mds state.
  The code knows this: `requests_service.dart:278` lists it as an *obsolete* label and migrates
  it to `Under Review` on load.

  statuses, such as Under Verification, Processing, or **Waiting Requirements**" — a status the

- `TERESA_RIZAL_MOBILE_WEB_ALIGNMENT.md` Section 1 documents a 14-status list containing
  "Ready for Release", which exists in *neither* codebase now. The doc is stale (last updated

Design tokens, by contrast, are exact: all 23 navy/brand/gold hexes in `app_colors.dart` match
`resources/css/app.css` 1:1. That part of the spec's parity claim verifies.

### 14 — LOW: five root files are committed with CRLF
`git ls-files --eol` reports `i/crlf` for `.gitignore`, `README.md`, `pubspec.yaml`,
`analysis_options.yaml` and `teresa_rizal.iml` — all part of the broken leftover
root scaffold (finding 5). There is no `.gitattributes`, so EOL handling depends on each
machine's `core.autocrlf`. A `* text=auto` was drafted and **deliberately not committed**:
it renormalises those five untouched files end-to-end, which would bury a crash fix under
pure line-ending churn. Worth doing on its own, together with finding 5's cleanup.

### 15 — LOW/MEDIUM: the repo cannot be cloned into a normal-depth path on Windows
Found by trying to verify the push from a clean clone. `git clone` into a scratch
directory ~100 characters deep **checked out nothing** — all 504 files reported as
deleted, with git suggesting `git restore --source=HEAD :/`. The cause is Windows'
260-character `MAX_PATH` with `core.longpaths` unset (its default).

The longest tracked path is **210 characters**, and the top offenders are all in
`Reference_forms/` — e.g. a 210-char DILEEP guideline PDF under
`Reference_forms/Placeholders/Tulong/`. That leaves under 50 characters of headroom for
the clone directory. The working clone used for this sweep sits at a 43-character path
and fits with 7 characters to spare; anything deeper silently produces an empty tree
that looks like catastrophic deletion rather than a checkout failure.

Two mitigations, and the second is the real one:

- `git config --global core.longpaths true` on every Windows machine that touches this
  repo (per-machine, easy to forget, and does not help a fresh contributor).
- Remove `Reference_forms/` — which findings 1 and 13 already require on privacy
  grounds. Doing that drops the longest path to well inside `MAX_PATH` and makes this
  finding disappear as a side effect.

Verification was completed in a short path (`C:\tmp\ec_verify`): clean clone, **0 dirty
files**, `flutter analyze` clean in 66.6 s, **458 tests passed**, and `flutter pub get`
left `pubspec.lock` untouched — confirming the lock is reproducible now. The only
post-gate churn is 7 generated plugin registrants that Flutter rewrites with LF;
`git diff --numstat` is empty for all of them, so they are line endings only, not
content (see finding 14).

## Fixed in this round

Finding 3 (the permanent splash hang) is fixed, with the fix proven rather than assumed.

- All **six** services (`citizen_session`, `requests`, `balita`, `master_file`,
  `notifications`, `resident_profile`) now guard `_restore()`. The load flag is flipped
  and `notifyListeners()` fired from a `finally`, so the gate opens on every path.
  Unreadable state is discarded rather than retained; `CitizenSessionService`
  additionally clears the poisoned key so the next launch starts clean.
- All four enum decoders (`PostMediaType`, `AttachmentCategory`, `ReceiptType`,
  `ServiceCategory`) got an `orElse`, so one unknown value costs one field, not the
  whole collection. No unguarded `values.firstWhere` remains in `lib/`.
- New `test/corrupt_persisted_state_recovery_test.dart` — 8 cases over three shapes of
  bad payload (not JSON, wrong type, unknown enum value).

**The new test was watched failing before it was trusted:** with the fix stashed, all
8 fail, each reporting `<Service> never finished loading — the splash would spin
forever`. With the fix applied, 8/8 pass. Every one of the six services really did hang.

Also fixed: the finding-4 copy defect (`help_support_screen.dart` no longer advertises
`Waiting Requirements`, which the app migrates away and can never display); finding 8's
Android half (`android:label` was the snake_case `teresa_rizal` on the home screen —
iOS was already correct via `CFBundleDisplayName`); finding 10's stale comments; and the
non-reproducible `pubspec.lock` — the resolved 3.47.0 lock is now committed, so
`flutter pub get` no longer dirties the tree on either lane.

`CLAUDE.md` also no longer names only the Mac's rules path. Both lanes work this one
repo, so anything machine-specific has to name both or it silently excludes a lane.
